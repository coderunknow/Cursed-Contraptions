# v0.1.5 hotfix plan — devices missing from the creative inventory

## Report

*"I don't see any item in the game though I active the add on."* Both packs
import and enable, but the creative inventory contains none of the add-on's
items, so there is nothing to place.

## Root cause

Every item and anchor block declared:

```json
"menu_category": { "category": "items", "group": "itemGroup.name.miscellaneous" }
```

Current Bedrock item definitions require the creative `group` to be namespaced —
the schema documents the value as matching `^(?:.)+:(?:.)+$` ("the name also must
start with a namespace"), and the vanilla groups are exposed as
`minecraft:itemGroup.name.<group>`. The un-namespaced
`itemGroup.name.miscellaneous` fails that rule, so the game discards the
`menu_category` (and with it the creative placement) for all five items and all
five blocks. `/give` and the crafting recipes are unaffected, which is why the
devices were still reachable by command in earlier tests and the defect went
unnoticed until release-day play testing.

Secondary defect found while fixing it: nothing in the repository validated
creative registration at all, so the mistake could ship unnoticed.

## Fix

1. `tools/texturegen/build_assets.py` now emits a single, namespaced creative
   group, `cc:itemGroup.name.devices`, on every item and block, and writes
   `behavior_pack/item_catalog/crafting_item_catalog.json` (format version
   `1.21.60`, the same era as this pack's `min_engine_version`) declaring that
   group: icon `cc:item_iron_maiden`, name `cc:itemGroup.name.devices`, and all
   ten entries.
2. `resource_pack/texts/en_US.lang` gains
   `cc:itemGroup.name.devices=Cursed Contraptions (Devices)` for the group's
   hover label.
3. `tests/validate_build.py` gains a "Creative inventory registration" stage:
   every item and block must set a visible `menu_category` category
   (`construction`/`equipment`/`items`/`nature` — `none` is rejected because it
   hides the entry), any `group` must be namespaced, and every group must be
   defined in the catalog, list the declaring identifier, use a known icon, and
   have a localization key. The old value now fails the build.
4. Pack version bumped to `0.1.5` so a world that already has `0.1.4` installed
   accepts the update instead of keeping the cached pack.

## Verification

- Negative test: re-inserting `itemGroup.name.miscellaneous` on one item makes
  `tests/validate_build.py` fail with
  *"has menu_category group ... the group must be namespaced"*; restoring it
  returns the build to 0 errors.
- `npm test` (38 tests), `npm run typecheck`, `tests/validate_build.py`, and
  `./build.sh` all pass, and the packaged `.mcaddon` contains
  `item_catalog/crafting_item_catalog.json`.
- In-engine confirmation is still a manual step: see `tests/GAMETESTS.md` §7.
  Automated checks cannot open the creative inventory.

## Compatibility

No identifier, UUID, recipe, dynamic-property key, or balance value changed. The
only content change is where the items are filed in the creative menu, plus the
new catalog file; existing worlds keep their devices, captives, durability, and
reinforcements.
